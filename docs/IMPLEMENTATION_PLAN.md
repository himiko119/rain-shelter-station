# IMPLEMENTATION PLAN

## Phase 1 — 設計と基盤

- Git作業ブランチ、規約、企画、技術設計、テスト計画
- npm、Vite、TypeScript、Phaser、ESLint、Vitest、Playwright
- DOM shell、16:9 Canvas、テーマ、タイトル画面
- lint／typecheck／unit／buildを束ねる `npm run check`

完了条件: タイトルがブラウザ表示され、品質コマンドが動く。

## Phase 2 — 縦切り

- 純粋GameState／store／save validator
- 待合室と改札、移動、衝突、interaction hotspot
- 会話、ノート、所持品、ポーズ
- 赤い傘、2手がかり、正誤返却、記憶、時計、自動セーブ

完了条件: 通常入力で新規開始から赤い傘返却、再読み込み継続まで通る。

## Phase 3 — 全探索

- 5エリアと明示的な出口
- 6忘れもの、全手がかり、全乗客、全調査文
- 段階ヒント、誤返却、取り逃し復旧
- 時計、灯り、雨、空、エリア開放の連動

完了条件: 5品返却後の終電選択と、6品返却まで進行不能なく到達する。

## Phase 4 — 物語と結末

- 導入、短い記憶場面、真相
- A「終電」、B「始発」、C「雨宿り」
- 記録、クレジット、タイトル復帰、再プレイ

完了条件: 各条件境界を単体テストし、E2Eで3結末へ到達する。

## Phase 5 — 演出と操作性

- 雨、水面反射、駅灯、時計、夜空、雨上がり、フェード
- Web Audio、音量、ミュート
- キーボード／ポインター／タッチ
- 文字速度、一括表示、演出軽減、フォーカス、操作説明
- desktop／mobileレイアウト調整

完了条件: 1280x720と390x844で主要操作と表示が成立する。

## Phase 6 — 検証と修正

- 要件を覆うVitest
- 通常入力の短いE2E、セーブ／設定／削除、3結末
- 重大console／page error／asset失敗guard
- 指定10画面の撮影と実見確認
- プレイヤー視点の通し確認、重要度順の修正、再検証
- README、PLAYTEST_REPORT、最終 `npm run check`

完了条件: 主要コマンド成功、画面確認済み、既知制約が文書化され、意味のあるコミットが揃う。

## スコープ制御

安定性を損なう場合は、素材数、複雑なアニメ、音の種類を減らす。探索、照合、記憶解放、3エンディング、セーブ、最低限のタッチとアクセシビリティは削らない。
